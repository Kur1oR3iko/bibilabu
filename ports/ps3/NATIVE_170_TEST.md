# bibilabu PS3 1.7.0

本次按要求只在电脑生成 PKG，不复制到 U 盘。启用 HEN 后可覆盖安装，标题 ID 仍为 WILIPRB01。

## 功能变化

1. **断网恢复**：初始化失败不再变成永久失败状态。发现断线、DNS 失败或连接超时后，在浏览界面重新建立应用网络状态；默认约 15 秒重试，也可按三角键立即重连。先取消并结束所有 HTTP 工作线程，再清理 CURL/应用网络资源；借用的系统服务不会被当成自己创建的服务关闭。网络重试不清除账号。
2. **账号保存**：使用正确的 JSON 字符转义、完整写入、fsync、临时文件替换和 `.bak` 备份。只在 PS3 内置硬盘保存到 `/dev_hdd0/tmp/bibilabu_config.json` 与应用内部目录，读取并兼容这两个本地位置。登录凭证不会再写入或从 USB 导入。损坏的主文件可以回退到备份，显式退出登录会写入标记，防止旧备份自行重新登录。
3. **L1/R1 ±10 秒**：播放时 L1 后退、R1 前进 10 秒。使用 MP4 sidx 定位独立片段，不重新从视频开头下载；从关键帧解码并丢弃目标时间前的画面/音频。暂停时跳转会在新位置保持暂停。切换清晰度也会尝试保留当前进度。
4. **退出确认**：圆圈在分类层准备退出应用、或按 START 退出时，显示“确认退出吗”，默认选中取消。左右选择，叉键确认，圆圈取消。PS 系统菜单自己的退出流程不再额外叠加一次确认。
5. **真实清晰度菜单**：根据当前播放会话实际返回的可用 AVC DASH 视频流生成选项，过滤不支持的编码、尺寸和帧率；不再固定摆放三个档位。打开视频默认选最高可用档位；用户明确切换时若服务器未提供所选档位，会报明不可用，不假装已切换成功。
6. **部分播放失败**：视频详情请求及 JSON 解析上限由 256 KiB 调整到有界的 2 MiB，针对日志里 HTTP 200 但 body overflow 的失败。解码尺寸检查增加可识别的可见高度/填充高度变体、跳过帧处理，仍保留行宽、已分配缓冲边界及未知状态保护；所有异常尺寸都会记录具体值。
7. **布局**：分类和列表整体向左 28 像素、向上 20 像素移动（1280×720 逻辑坐标）。背景、页眉、底部提示及播放界面不跟着偏移。

## 这一轮建议验证

- 不联网打开应用，然后连接网络，留在应用内等待或按三角。检查列表能否恢复；正常退出再打开，检查账号是否保留。不要为了测试先清空配置。
- 播放超过 20 秒，按 L1、R1，核对时间变化与声音/画面同步；暂停后跳转，再继续。长 GOP 视频跳转可能需要短暂缓冲。
- 从列表按圆圈返回分类，再按圆圈，检查默认取消的退出弹窗；确认后正常退出。
- 找只有 480p AVC 的视频，菜单不应显示 720p；有 720p AVC 的视频应显示对应选项。HEVC/AV1 或超出本机当前边界的流不会被当作可播放档位。
- 重测之前 1280×718 的视频，以及之前提示无法播放的合集/长详情视频。

回传 `BIBI_PLAY.LOG` 与 `.previous`。重点标记 `NETWORK_REINITIALIZED`、`CONFIG_LOADED`、`SEEK_BEGIN`、`VDEC_PICTURE_DETAIL`。
本版日志身份为 `BIBILABU_PS3_NATIVE_170`。

## 实现边界

网络恢复逻辑和凭证备份在主机模拟/回归中通过，但 DNS 的实际恢复仍需 PS3 实测。服务器真实使会话过期时仍可能需要登录。
跳转的分段提取及 AVC/AAC 解码通过主机验证，PS3 的首次跳转延迟、暂停恢复及音画同步仍待实机结果。
清晰度选项反映服务器提供的本机可选流，不能预先证明每个视频的全部编码数据都能被固件正确解码。

本版没有开启弹幕或 1080p。可行性、内存预算与工具链限制见 `DANMAKU_1080_RESEARCH.md`。
