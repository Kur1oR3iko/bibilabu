# bibilabu PS3 1.9.1

## 修复依据

用户报告 1.9.0 播放卡顿/音画不同步、退出慢，1080p 无法选择播放。U 盘的 1.9.0 日志记录了两段 720p AVC 播放和大量 `LOG_QUEUE_DROPPED`，没有保留下完整的 1080p 失败与退出过程。因此没有把某一个等待或线程直接认定为全部卡顿的根因。

代码检查发现两项片源误判：SPS VUI 解析漏掉 `pic_struct_present_flag`，HRD 字段读取顺序也不正确；同时 1.9.0 要求 `fixed_frame_rate_flag=1`，导致普通 MP4 AVC 被拒绝。保存的真实 Bilibili SPS 经 FFmpeg `trace_headers` 独立解析，结果为固定帧率标志 0、重排帧数 4、DPB 6；旧解析器错误读成无 bitstream restriction。

## 变化

- 修复 VUI 字段顺序，1080p 根据 MP4 实际样本时间探测不超过 30fps；允许正常的固定帧率标志为 0，也允许 API 缺少帧率时进入媒体探测。读取后续视频包时继续检查帧时间，保留 AVC 8-bit/4:2:0、1920×1088 编码尺寸、DPB、参考帧和码率限制。
- 清晰度请求失败时区分账号/视频未返回画质、帧时间超限和 SPS 不兼容；失败日志会保留所请求和实际返回档位。超宽 1920×720 不再仅因高度等于 720 而误删 1080 档。
- 同一视频帧无需每个显示刷新周期重新运行 YUV 着色器；无变化时重复已完成的显存帧，保留 PS 系统菜单/OSK 期间的完整绘制。记录视频处理、UI 合成、GPU 等待和 flip 等待耗时，以及音画时钟差。
- 提示音一次生成波形，跨 256 样本块保持连续；空闲时休眠，播放时静音并减少轮询，线程优先级低于媒体输出。
- 日志从逐行多次写盘改为最多 16 KiB 批量写，先写内置硬盘，再写 USB；增加毫秒时间戳，繁忙时也定期同步。
- 退出时同时取消各后台任务，在单独线程释放资源；主线程继续 flip 并在 3 秒后结束等待。日志最后排空最多等 750 ms。超时后保留尚在使用的资源，交给进程退出回收，不在后台线程仍运行时释放其内存。系统 OSK 自己的卸载阶段另有最多 2 秒等待；这些数值不是 XMB 返回速度的实机承诺。
- 新增原创银白 B/播放符号 Logo：`assets/logo-mark.svg` 为可编辑源文件，`assets/logo-512.png` 为方形预览，`assets/ICON0.PNG` 为 320×176 PS3 安装图标。

## 本轮检查与实机步骤

构建流程包括已有 API/HTTPS、Range、MP4、音频、账号、异步列表和 UI 检查；新增实际 1080p24/30 MP4 解封装与主机解码，验证 Level 5.1 归一化、1080p60/超出 DPB 的拒绝，以及提示音跨块连续性。以构建清单记录的结果为准，主机解码不等于 PS3 解码性能通过。

1. HEN 后覆盖安装 1.9.1，确认 XMB 图标更新；若仍显示旧图标，可重进游戏列表后观察。
2. 先重播上次卡顿的 720p 视频，观察音画同步，隐藏控制栏后再播放 1 分钟；然后选择普通 1080p24/30 AVC 视频。
3. 切换清晰度、L1/R1 跳转、暂停恢复，最后分别用应用退出确认和 PS 菜单退出。
4. 保留 `BIBI_PLAY.LOG` 与 `.previous`。重点为 `AVC_RATE_PREFLIGHT`、`BILI_QUALITY_UNAVAILABLE`、`PERF`、`VIDEO_CLOCK`、`EXIT_STEP` 和 `EXIT_CLEANUP`。内置硬盘同样保存 `/dev_hdd0/tmp/BIBI_PLAY.LOG` 和应用目录内日志。

本版只在电脑生成，不自动复制到 U 盘。PS3 新路径的性能改善、1080p 兼容性和退出时间仍须实机确认。
