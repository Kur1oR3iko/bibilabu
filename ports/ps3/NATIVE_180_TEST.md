# bibilabu PS3 1.8.0 — YUV / Aero

本版包含 1.7.0 的网络恢复、内置硬盘凭证备份、±10 秒跳转、退出确认、动态清晰度与布局改动，另加入新的 YUV 视频输出和轻量 Aero 播放界面。
按要求只保存在电脑，不复制到 U 盘；1.7.0 安装包保留在同一 dist 目录供对照。

## 新的播放路径

- 所有本客户端支持的原生 AVC 视频都请求 `VDEC_PICFMT_YUV420P`，不再向固件请求整帧 ARGB。
- 主内存保留 Y/U/V 三个平面，RSX 使用三个纹理完成 BT.601/BT.709、完整/有限范围的转色与缩放。没有 CPU YUV→RGB 热路径。
- 必要时只移动未满足 128 字节对齐的色度平面；输出带越界哨兵。当前显示帧仍由 GPU fence 保护，归还后才复用。
- 1280×720 的十槽输出池请求约 **14 MiB**，此前约 **40 MiB**；864×480 约 **6 MiB**，此前约 **20 MiB**。这不包含解码器内部工作区、网络、字体等内存，不等于整个应用只有这么大。
- 图形程序另用约一帧大小的 VRAM 深度缓冲保证有效渲染表面（1080p 显示模式约 8 MiB）。主内存与 VRAM 分别预算。

## Aero 播放界面

半透明深蓝面板、圆角、柔和高光、细亮边框、圆形暂停按钮与新的进度条。视频会真实透过面板，而不是一张画着“玻璃效果”的不透明背景。

控制层采用预乘 alpha，GPU 负责混合；约 140 ms 淡入、200 ms 淡出。内容在状态/时间变化时更新，淡入淡出期间不要求 CPU 每帧重画整层。没有实时模糊或折射处理。

浏览页仍使用现有 XMB 布局与系统壁纸。清晰度最高仍为受支持的 720p AVC；没有顺便开启尚未验证的 1080p 或弹幕。

## 这轮实机重点

1. 启用 HEN 后覆盖安装，先播放已知能正常播放的 480p 视频，再测试 720p。
2. 检查画面是否上下颠倒、黑屏、偏红/偏蓝、黑白灰阶异常；观察人物肤色与字幕边缘。
3. 测试带裁切的视频（如 1280×718、852/854×480），确认画面比例和边缘正常。
4. 三角键显示/隐藏控制条，观察透明面板和淡入淡出；暂停后再继续、L1/R1 跳转、切换清晰度。
5. 连续播放数分钟，换视频五次，再用 PS 菜单退出，确认没有明显退化或内存累积。

日志应出现 `BIBILABU_PS3_NATIVE_180`、`RSX_YUV_READY`、`YUV_OUTPUT_READY`。
720p 的 `frame_pool_bytes` 预期为 `14680064`，实际尺寸不同会有不同结果。
如果出现 `YUV_OUTPUT_GUARD_CHANGED`、`YUV_LAYOUT_REJECTED`、`RSX_BLIT_FENCE_TIMEOUT`，提供完整 `BIBI_PLAY.LOG`。

## 已完成的离线检查

- 原有启动/退出 ABI、导入表、网络、账号、索引跳转、API、音频与界面回归。
- YUV 对齐、重叠平面搬移、缓冲边界与实际帧池预算检查。
- 自有 RSX 汇编的程序头、长度、顶点输入、纹理取样指令验证。
- 四套矩阵与独立 FFmpeg 转色结果比较，8-bit 误差在测试阈值内。
- Aero 图层预乘 alpha 约束、透明区域与零透明度不改变底图的检查。

这些检查不代表 PS3 GPU 路径和性能已经通过。效果图是实际 UI 代码的主机合成预览，视频底图为示例；颜色、GPU 同步及帧率需要本轮实机验证。
