# bibilabu PS3 1.9.2 — 播放缓冲与控制栏缓存

## 实机依据

1.9.1 实机日志保存于 `evidence/hardware-191-playback.log`。用户使用另一网络的 Wi-Fi；PS3 直接访问 B 站 CDN，不经过开发电脑。

- 720p 有连续区间接近 30 帧、音画差约 13–25 ms；但控制栏重画平均可达约 100 ms（如 5 次重画共 549 ms），会阻塞同一主线程的视频供给。
- 1080p 已实际打开 1920×1088 AVC、30000/1001 fps。约 126–136 秒区间，视频压缩包缓存反复为零，音频仍推进；音画差从约 -2 秒恶化至 -6.3 秒。
- 同一区间，5 秒内视频主线程处理约 0.5 秒、GPU 等待约 0.1–0.15 秒，不能据此判断 Cell 或 RSX 已饱和。每个 256 KiB 请求常用约 0.4–1.3 秒；下载供给和音画同步策略存在明确问题。
- 本次片源 1080p 视频平均约 3.16 Mbps，音频另约 0.18 Mbps，复杂画面瞬时码率会更高。平均码率不足以保证 Wi-Fi/CDN 波动下持续播放。
- 1.9.1 的本次退出清理日志为 26 ms，各阶段正常完成。

## 改动

1. 视频与音频分别用各自线程和 CURL 句柄下载、解封装，避免一个媒体请求串行拖住另一个。
2. 视频压缩数据改用固定 16 MiB 环形区，最多 128 个包描述符，按真实包长度存储；不再每帧预留 512 KiB。另有一个 512 KiB 转换暂存区。30fps 时，包数量上限从约 1 秒提升到约 4.3 秒，不进行逐包堆分配。
3. 播放阶段视频 Range 扩为 1 MiB，音频保留 256 KiB；维持 TLS 验证、206 范围、ETag 和长度校验。记录请求总耗时、首字节、连接、TLS 与新连接次数。大范围请求超时为 12 秒，仍支持取消。
4. 首次播放通常先预取约 2.5 秒视频；短片到 EOF 或缓冲容量接近上限可提前开始。视频将断粮或严重落后时，暂停音频端口和音频时钟，继续补视频；包和解码画面都达到恢复条件后再同步播放。手动暂停与自动缓冲分别处理。
5. Aero 静态玻璃层、标题、画质和按键说明缓存一次，后续只画进度、时间、状态等动态部分；新增约 3.52 MiB 静态 UI 缓存，进程清理时释放。

本版不会自动把用户选中的 1080p 偷换成低清晰度。网络持续吞吐不足时仍需要缓冲，无法凭客户端修改保证所有网络都能流畅播放。

## 检查与复测

构建回归包括：五万次变长包并发读写、数据区和 32 位计数器回绕、背压和所有权；扩大/缩小 HTTP 窗口与跨边界数据一致性；断粮/恢复门限；缓存 UI 与重新完整合成逐像素一致；已有 API/HTTPS、音频、账号、1080p24/30、60fps 拒绝和 PS3 ABI/安装包检查。实际结果看本轮构建日志与清单，这些检查不等于 PS3 或 Wi-Fi 性能通过。

覆盖安装后，优先重播上次同一段 720p 和 1080p，分别观察控制栏显示与隐藏时的流畅度、自动缓冲时声音是否同步停止、恢复后是否重新同步，再试暂停/跳转/退出。

日志重点：`HTTP_RANGE_OK` 新增的耗时字段、`VIDEO_BUFFERING_BEGIN/END`、`VIDEO_CLOCK` 中的 `v_buffer_ms/v_rebuffers/skew_ms`，以及 `PERF compose_ms`。若仍卡顿，需要用新日志判断吞吐是否提高，以及缓冲时钟是否按预期工作。

安装包仅保存在电脑，不自动写入 U 盘。
